## 二、知识要点 ↔ 实现对照

**1. 批次编码、业务关系与权限划分**
- 批次编码规则：`AG` + 建档日期 + 流水号；溯源码 `TC` + 流水号。
- 业务关系：批次 →（种植→采收→质检→物流→销售）→ 异常处置/更正，全部以 `batch_id` 关联。
- 权限划分：RBAC（`sys_role` / `sys_permission` / `sys_role_permission`），后端 `@PreAuthorize` 细粒度控制 + 前端菜单按角色过滤；链上另有 `authorized` 地址白名单双重校验。

**2. FISCO BCOS 节点、账户、交易回执与事件；Solidity 合约**
- 4 节点联盟链，SDK 证书（`ca.crt/sdk.crt/sdk.key`）接入。
- `Traceability.sol` 实现：批次唯一登记（`registerBatch`，重复报 "batch already exists"）、业务记录追加（`addRecord`）、授权主体校验（`onlyAuthorized` 修饰器）、状态约束（`NORMAL→ABNORMAL→CLOSED` 单向流转）、历史保留（`Record[]` 数组追加）、追加更正（`addCorrection`）。
- 交易回执：`sendTransaction` 校验 `status`（FISCO 0x0=成功），失败抛异常，绝不以失败回执记为已存证。
- 事件：`BatchRegistered / RecordAdded / BatchMarkedAbnormal / BatchDisposed / BatchClosed / CorrectionAdded / Authorized`。

**3. Spring Boot、Vue、MySQL 与 Java SDK 协同；二维码、文件摘要、链上链下关联、异常处理**
- 后端 Spring Boot + MyBatis-Plus + MySQL；前端 uni-app（Vue3 语法）；链交互走 Java SDK `BcosClient`。
- 二维码：`app.trace-url-prefix` + QR 生成工具；扫码即达溯源页。
- 文件摘要：上传图片/报告/视频计算 SHA-256（`sys_file.file_hash`），业务数据摘要走 `DigestHelper`，链上存 `dataHash + fileHash`。
- 链上链下关联：`chain_record(tx_hash, block_number, biz_type, batch_no, data_hash, status)` 一一对应。
- 异常状态处理：检测不合格 → `markAbnormal` 限制销售 → `disposeAbnormal` 处置闭环；录入错误 → `addCorrection` 追加更正（不删历史）。

## 八、两种链上接入方式说明

1. **Java SDK（主链路）**：后端 `BcosClient` 加载 `config.toml` + 证书 + `Traceability.abi`，`sendTransaction`/`call` 封装，交易以回执 `status==0x0` 判定成功。
2. **WeBASE-Front HTTP（扩展，`/trans/handle`）**：不依赖 SDK，业务侧只发 HTTP POST；本地签名用户 `agri-admin`（`0xf19449c2…`）已建，演示合约 `StorageCenter`（`0x26e59c7c…`）已部署并跑通「查询→写入→回执→事件」全流程；同时 HTTP 只读可直接读生产 `Traceability` 合约。

> 两种方式指向**同一条链、同一套数据**，可交叉验证（区块高度一致、交易 hash 一致）。
