# 演示素材说明

本目录存放实训任务书「三、素材准备」要求的模拟质检报告与农产品图片，设计文档中引用的流程图、用例图，以及系统实际运行的界面截图。

> 所有质检报告均为**教学实训场景下的模拟文件**，机构名称、检测人员、数据均为虚构，不具有法律效力。报告正文中已包含相应声明。

## 二、三份质检报告与演示数据的对应关系

`sql/data.sql` 中 `biz_quality_report` 的 `file_hash` 字段，记录的就是本目录下对应 PDF 的真实 SHA-256。也就是说，**用这三份文件做演示时，系统的「报告摘要校验」结果是真实成立的**，不是硬编码的假数据。

| 报告编号 | 文件 | SHA-256（前 16 位） | 字节数 | 判定 | 对应批次 |
| --- | --- | --- | --- | --- | --- |
| `JC20260512-001` | `JC20260512-001_红颜草莓_质检报告.pdf` | `85edf9559ed2da99` | 31230 | 合格 | `AG20260512001`（SOLD） |
| `JC20260515-002` | `JC20260515-002_小白菜_质检报告.pdf` | `bc22b7400e439f5e` | 32402 | 不合格 | `AG20260515002`（ABNORMAL，农残超标） |
| `JC20260522-005` | `JC20260522-005_脐橙_质检报告.pdf` | `848f75d007af1cb5` | 31895 | 不合格 | `AG20260522006`（ABNORMAL，重金属超标） |

另外 4 条质检记录（`JC20260517-003`、`JC20260519-004`、`JC20260525-006`、`JC20260528-007`）的 `file_hash` 为 `NULL`，表示这些是"只有检测数据、未上传报告原件"的记录。演示时如果对这批批次做摘要校验，系统会如实提示"报告摘要缺失"，而不是伪造通过——这正好可以用来讲解"存证不等于有报告"这一点。

### 校验方法（可手工复核）

```bash
# Windows PowerShell
Get-FileHash "docs\assets\samples\JC20260512-001_红颜草莓_质检报告.pdf" -Algorithm SHA256

# macOS / Linux
shasum -a 256 "docs/assets/samples/JC20260512-001_红颜草莓_质检报告.pdf"
```

计算结果应与上表完全一致。若有人修改了 PDF 任意一个字节，摘要就会变化，系统在上传同一报告号时会拒绝覆盖，或在一致性校验中判定为"摘要不一致"。

## 三、演示时怎么用

1. **质检报告上传**：用 `inspector01` 登录 PC 端 → 质检管理 → 上传报告 → 选择 `docs/assets/samples/` 下的 PDF。
   系统会计算并回显 SHA-256，与上表比对即可证明"文件摘要"确实来自文件本身。
2. **报告摘要核验**：进入批次详情 → 质检报告卡片 → 点击「校验报告摘要」，系统重新读取链下文件并计算摘要，与数据库/链上值比对。
3. **农产品图片**：`farmer01` 登录 H5 → 农事记录 → 新增 → 拍照/从相册选择 `products/` 下的图片。
   图片同样会计算 SHA-256 后随农事记录一并上链，可用于演示"图片也被存证"。
4. **篡改演示**：直接修改数据库某条记录的字段（如把采收数量改掉），再点「链上链下一致性校验」，系统会指出摘要不匹配——因为链上的摘要无法被同步篡改。

## 四、替换为自己的素材

- **报告**：用任意 PDF 替换，只需把 `biz_quality_report.file_hash` 更新为新文件的 SHA-256 即可；`file_name` 同步改名。
- **图片**：直接替换 `products/` 下的 jpg 文件，系统不依赖固定文件名，只要上传成功即可。
- **图（流程图/用例图）**：修改 `.svg` 源文件后用任意工具导出 PNG，或直接用浏览器打开 SVG 截图。SVG 中的文字可编辑，中文使用微软雅黑/苹方字体，跨平台显示一致。

> 注意：`products/` 下图片与 `samples/` 下 PDF 合计约 1 MB，可以正常提交到 Git；若替换为手机原图（单张 3~8 MB），建议先压缩到 1280px 宽，避免仓库膨胀。
