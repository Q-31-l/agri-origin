# 运行截图

本目录存放系统**实际运行**时的界面截图，用于毕设报告插图与答辩材料。

截图采集方式：按 [docs/deploy.md](../../deploy.md) 启动 MySQL + 后端 + 两个前端后，
用无头浏览器登录对应账号逐页截图。数据全部来自 `sql/data.sql`，未做任何手工修饰。
三端统一工程（`frontend/uni-app`）的截图由 `frontend/uni-app/scripts/e2e-pc.js` 自动采集，
每次执行会覆盖 `uni-pc/` 并写出 `report.json`（包含逐页 DOM 文本与 0 报错记录）。

> `uni-pc/` 与 `uni/` 下的现存图片于 2026-11-06 在线上环境（`http://8.130.105.150`）重新采集，
> 对应真实四节点链；`report.json` 仍是最近一次本地 e2e 运行的记录。

## 关于存证状态

两类截图对应两种真实环境，都不是占位图：

- **`uni-pc/` 与 `uni/`**（当前线上部署的三端统一工程）：取自 FISCO-BCOS 2.9.1 四节点真实链，
  存证状态为「已上链」，交易哈希与区块高度可直接在链上回查（例如 `pc-chain.png` 显示
  区块 `#177`、存证 165 条、成功率 100%）。
- **根目录 `pc-*.png` / `h5-*.png`**（独立 PC / H5 工程）：采集于 `chain.enabled=false` 的演示模式，
  存证如实标记为 `SKIPPED`，一致性校验提示「未存证」，**不伪造交易哈希**。

## 重新采集

```bash
# 1. 启动三个服务（数据库、后端、前端）
# 2. 用无头浏览器脚本采集（需 puppeteer-core + 本机 Edge/Chrome）
node shoot.js
```

采集脚本建议放在仓库外，避免把开发依赖带进版本库。
